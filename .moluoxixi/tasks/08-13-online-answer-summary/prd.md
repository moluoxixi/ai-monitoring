# 在线模型回答摘要与渠道回退

## Goal

任务完成通知同时包含用户任务摘要和最终回答摘要，让用户在不打开监控页面的情况下了解“问了什么”和“回答了什么”。回答摘要由低频在线模型调用生成，并在渠道受限时自动回退。

## Background

- 当前完成通知只显示 `任务摘要`。
- Codex notify 和 session JSONL 两条采集路径都能接触最终回答，但现有实现有意不把回答写入事件。
- 项目已有本地 JSON 凭据配置、原子替换、API 状态不回显密钥等安全惯例。
- 用户明确要求只支持在线模型，不接入本地模型。

## Requirements

- R1. 完成通知在有回答摘要时显示稳定的两段结构：`任务摘要` 和 `回答摘要`；失败通知维持现有失败消息结构。
- R2. 从 Codex notify 的最终 assistant message 以及 Codex session 的最后 agent message 获取待摘要文本；子代理会话继续不产生通知。
- R3. 成功任务的最终回答在截断和敏感信息清洗后写入专用数据库列，仅单任务详情接口返回；事件列表、投递列表、通知正文和日志不得包含完整回答。
- R4. 内置 Groq、OpenRouter、Google Gemini 三个渠道，并提供各自官方 API Key 获取链接。
- R5. 除内置渠道外提供一个 OpenAI-compatible 的“自定义渠道”，允许配置 Base URL、模型和 API Key。
- R6. 所有渠道使用 OpenAI-compatible Chat Completions 的最小交集字段；渠道按照用户配置顺序依次调用。
- R7. 任一渠道收到 HTTP 429 后立即回退，并冷却到服务器本地时间的次日零点；当天后续任务直接跳过该渠道。其他鉴权、额度、容量、超时及 5xx 错误也不得阻塞回退。
- R8. 所有在线渠道不可用、未配置或返回无效内容时，仍发送原有任务摘要通知，不让摘要失败阻塞消息投递。
- R9. 设置界面支持查看渠道是否已配置/启用、配置或解绑渠道、调整回退顺序；API Key 永不回显。
- R10. 配置文件使用版本化 JSON、受限文件权限和原子替换；配置或解绑后清除该渠道的错误/冷却状态。
- R11. 消息列表点击后打开任务详情，展示本次提问、完整回答或摘要回退、失败原因和各通知渠道投递状态；不依赖 Phoenix 或其它外部追踪平台。
- R12. 不接入 Phoenix、Grafana、Prometheus、Loki、Alloy、Tempo 等额外监控栈，当前产品定位为任务与对话记录中心。
- R13. 提供可选 Docker Compose 部署，镜像内包含通知中心、Apprise、OpenClaw 及固定版本的 QQ/微信插件；运行数据和机器人状态必须持久化且不进入 Git。

## Acceptance Criteria

- [ ] AC1. Codex 完成事件带最终回答时，模型成功后通知正文包含非空的 `任务摘要：...` 与 `回答摘要：...`。
- [ ] AC2. 完整回答只出现在单事件详情；API Key 以及临时 `answer_source` 不会出现在事件列表、投递列表、渠道状态、日志或 API 错误中。
- [ ] AC3. Groq、OpenRouter、Gemini 和自定义渠道均可配置；前三者展示正确的官方 API Key 页面。
- [ ] AC4. 第一渠道返回 429 时，同一次摘要请求调用下一渠道，并将第一渠道标记冷却到次日；同日再次摘要不会调用第一渠道。
- [ ] AC5. 未配置渠道或全部渠道失败时，事件与通知仍正常产生，通知至少包含任务摘要。
- [ ] AC6. session watcher 能保留最后一段 agent message 直到终态并在终态后清空，且保持子代理过滤和失败脱敏行为。
- [ ] AC7. 重复终态事件可以补全缺失的回答摘要，不破坏现有任务摘要和失败消息补全规则。
- [ ] AC8. 设置 UI 在桌面和移动宽度下无文本溢出或控件重叠，密钥输入使用密码控件。
- [ ] AC9. 后端测试、前后端类型检查和生产构建通过。
- [ ] AC10. 旧 SQLite 数据库启动时自动增加可空的回答列，不重建或丢失历史事件。
- [ ] AC11. Claude/Qoder 成功 Stop 能转发明确的 assistant 回答字段；失败事件不得保存回答；缺失 turn ID 的连续任务不得相互覆盖。
- [ ] AC12. Docker 部署可构建通知中心并启动 OpenClaw Gateway，健康检查通过；宿主 Codex session 以只读挂载接入，停止或重建容器不丢失数据库和机器人登录状态。

## Out Of Scope

- 本地 Ollama、LM Studio 或任何离线模型。
- 自动发现或承诺某个渠道的永久免费模型及配额。
- Anthropic 等非 OpenAI-compatible 原生协议适配。
- Grafana、Prometheus、Loki、Alloy、Tempo 等基础设施监控增强。
